## Guest checkout: offer sign-in once, never block the order

Requested: a signed-out shopper who presses **Place order** on `/checkout` should be shown the
sign-in card **once**, and cancelling it must not block the order — it goes through as a guest.

### Files

- **New** `src/app/_lib/auth-gate.ts` — `requestSignIn(): Promise<boolean>` plus
  `AUTH_REQUEST_EVENT` / `AuthRequestDetail`. A `window` CustomEvent carrying its own
  `resolve` + `handled` channel, so a request nobody is listening for resolves `false`
  immediately instead of hanging the button.
- `src/app/_components/navigation/Navigation.tsx` — owns the card, so it answers the request.
  Added `signInGate` ref + `settleGate()`. `close()` now settles the gate `false` (one place
  every dismissal runs through), and `toggle()` delegates to `close()` when closing so the
  account button can't strand a waiting caller. `onCustomer` was wrapped: a gated sign-in
  resolves `true` and closes the panel.
- `src/app/_components/sections/Checkout.tsx` — `place` is now `async`. On the first press it
  asks `currentCustomer()`; if nobody is signed in it awaits `requestSignIn()` and places the
  order either way. New `offeredSignIn` ref (once per visit) and `offering` state (feeds the
  button's `disabled`).

### Notes

- `placeOrder` already supported guests end to end (`p_user_id: null`), so **no server change
  was needed**.
- Checked `currentCustomer()` at press time rather than reusing the page's `accountName` from
  the mount effect — a session that expired mid-form would otherwise file the order against an
  account nobody is signed in to.

## Ritual: stranded cap on upward scroll (root cause found and fixed)

The "Ritual plays twice when scrolling up" report traced to **one** defect in
`src/app/_components/three/useBottleUncap.ts`, in the master controller's Zone 3.

The cap's showcase close is a **timed** tween (`gsap.to(cap.position, …)`) chasing the scroll
position across 3.9 → 4.7 screens. Zone 3's upward branch only called
`gsap.killTweensOf(cap.position)` — which **freezes the cap wherever it happens to be**. So any
reversal inside that window left the cap stranded partway (or fully) lifted:

- reverse mid-glide → cap frozen ~60% up;
- reverse between 3.0 and 3.9, before the close starts → cap frozen fully lifted all the way up
  to the 2.5-screen reset.

That is scene 1 (detached cap, no mist). Scene 2 was the next downward pass re-running the whole
uncap + spray + steps sequence — the two together read as the scene "creating 2 times".

**Fix:** the upward branch now *seats* the cap at `baseCapY` instead of freezing it, guarded on
`!gsap.isTweening(cap.position)` so the tween starts once and is allowed to finish rather than
being restarted every wheel tick.

Also fixed while in there:

- Zone 3 announced `SPRAY_COMPLETE_EVENT` on **every** `onUpdate` once `closeProgress >= 1` — i.e.
  on every wheel tick between 4.7 and 5.0 screens, each one re-running `reveal()` in `<Ritual>`.
  Now guarded by a `hasAnnouncedClose` flag, reset in Zone 1 and Zone 2.
- `SHOWCASE_CLOSE_DURATION` was dead (left over from the rewrite — the close became a
  scroll-driven glide). Replaced with two named constants for the durations actually in use:
  `CLOSE_CHASE` (0.15) and `RESEAT_DURATION` (0.25). The file now lints with **zero** warnings.

Hand-traced the four passes (full down, full up, reverse mid-close, reverse before the close) and
the fix holds on each: no cap detach and no mist on the way up, and the open-bottle reading window
on the way down is untouched.

## Liquid colour did not match the button — `juiceColor` was applied twice

Reported: the 3D liquid reads grey-brown while the button (`--accent`) is a sage/olive, and the
button is the one that is right.

**Root cause: `juiceColor` ran twice on the same colour.** It is a channel subtraction, so it
compounds rather than being idempotent:

- `PersistentBottle.tsx:45` passes `liquidColor={juiceColor(variant.hex)}` — already treated.
- `BottleScene.tsx` then did `const juice = juiceColor(accent)` on that same prop.

For Parada (`hex #b7bb81` → `readableAccent` `#7c7f56` → first pass `#465000`) the second pass
produced **`#262100`**, a near-black brown with no green left. At the liquid's half opacity over
the parchment that composited to a grey-taupe — exactly what the screenshot shows.

Measured from the screenshot and from the maths:

| | hue | sat | val |
|---|---|---|---|
| `#7c7f56` button `--accent` (target) | 64° | 32% | 50% |
| `#a7a59a` liquid before (sampled from the PNG) | 51° | **8%** | 65% |
| `#9d9e70` liquid after (predicted) | 61° | **29%** | 62% |

**Fix** — `BottleScene.tsx` now treats the prop as already-treated and only juices the raw
`--accent` token fallback:

```ts
const juice = liquidColor ?? juiceColor(readCssToken("--accent", "#b87333"));
```

Also corrected the `liquidColor` prop doc, which claimed the raw hex was acceptable.

### The convention (now consistent)

Callers pass a **`juiceColor(...)` result**, never the raw hex — that is what `BottlePreview`
documents and what `PersistentBottle` and `MegaMenu` both do. `BottleGltf` does no treatment of
its own, so the transform happens exactly once per path.

### Latent problems found, NOT fixed (need a decision)

- **`juiceColor`'s generic branch destroys hue.** It subtracts a flat 30/36/36 per channel and
  scales each by a different factor (0.96 / 0.76 / 0.78), which crushes G and B harder than R and
  skews every hue toward brown. Sage `#7a7e68` → `#584435`. Only the two hard-coded catalogue
  branches save Parada and Boom Shell.
- **Those branches match on a magic string.** They key on `readableAccent(hex)`, so they fire only
  while a fragrance's *darkened* accent happens to equal `#7c7f56` or `#9a7177`. Any new SKU whose
  `readableAccent` collides silently inherits another fragrance's liquid colour.
- `src/app/_components/three/bottle-materials.ts` is **dead** — nothing imports it, and its
  transmissive `LIQUID_MATERIAL` describes an approach the live code deliberately does not use
  (nothing refracts; see `GLASS_MATERIAL` in `BottleGltf`).
- `BottleScene.tsx` carries 5 unused imports (`AgXToneMapping` is used, but `ACESFilmicToneMapping`,
  `Box3`, `Vector3`, `Object3D`, `useScrollScene` are not) and 3 `react-hooks/refs` **errors**
  from passing the `refs` bundle as a prop. All pre-existing, all from the rewrite; left alone to
  avoid churning a file the user may still be refactoring.

## Bottle realism pass — the glass rim and the liquid

Reported: the vessel "prickles in the eyes" and does not look real. Structure and design to stay
untouched, so this is all materials and shaders in `BottleGltf.tsx`.

### Why it glared (diagnosed, not guessed)

`applyGlassEdge` compounded two exponents: `pow(1 - cosθ, 2.5)` fed into `pow(fresnel, 2.2)` is an
effective **5.5**, which squeezes the highlight into the last pixel or two of the contour. That
tight, it stops reading as light on a curved surface and reads as a stroke drawn round the shape.
On top of that the glint was added as unattenuated `vec3(glint)` and the alpha ceiling was `0.85`
on a body that is only 8% opaque — a hard white edge on a nearly invisible fill. The cap sleeve was
the worst of it at `glintStrength 0.95 / alphaGlint 0.60`.

**First attempt over-corrected and made the vessel nearly invisible.** Softening the falloff *and*
halving the strengths was two reductions at once: the alpha ceiling went `0.85 → 0.42`, so the glass
lost its silhouette entirely against the parchment. An 8%-opaque white shell on cream is very
nearly nothing — **the rim is the only thing that makes the vessel visible**, so it has to be
strong; the trick is being strong without glaring.

**Corrected values** (v10): one exponent `3.0`, warm glint, ceiling `0.62` — the middle between the
glaring `0.85` and the invisible `0.42`. Bottle `0.40 / 0.44 / 0.20`, cap `0.46 / 0.46 / 0.26`,
glass body opacity `0.08 → 0.10`.

Also made the rim **directional**, which is the other half of why an even ring reads as drawn:
`lit = smoothstep(-0.35, 0.85, dot(N, keyDir))` weights the glint toward the lit side
(`mix(0.30, 1.0, lit)`) and the contour toward the shadow side (`mix(1.0, 0.55, lit)`), so the two
together describe a solid rather than a shape. It reads the live normal, so it follows the variant
spin and the showcase tilt.

### The lights had been rewritten — worth knowing

`<BottleScene>` is no longer the three lights it was: it now has **six directional lights plus
`ambientLight 0.5`**, all low-intensity (0.18–0.30) with the env map doing most of the work. The key
is the **only warm-tinted and brightest** one, `[3.2, 2.4, 4.2]` at `0.30` in `#fffaf2` — which is
what `keyDir` is normalised from. My first `keyDir` was built from a stale read of the old lights;
a check that derives the direction from `BottleScene.tsx` and compares caught it, and will catch it
again if the lighting moves.

### Why it looked flat

The liquid was a uniform `opacity 0.3` fill with `clearcoat: 0` — a single flat tone, which the eye
reads as paint. Added the two cues a real fill has, injected into the fragment shader at
`dithering_fragment`:

- **Beer-Lambert depth** — a vertical gradient over the mesh's own extent, squared so it stays
  gentle through the middle and only bites near the bottom.
- **A meniscus** — a bright band at the top of the column where surface tension pulls the liquid up
  the glass and the curve catches the key light. The strongest single cue that the top of the fill
  is a surface.

Plus `clearcoat 0.35` on the liquid so the surface carries its own specular. The body range is
measured from `liquid.geometry.boundingBox` and passed as uniforms rather than hardcoded, and the
gradient keys off the *undeformed* `position.y` via a new `vBodyY` varying, so it stays anchored to
the glass while the surface sloshes.

**Dip tube:** was `opacity 0.80` pure white — a hard bright line laid over the bottle. Now `0.32`
and warm off-white (`#e6e0d4`).

### Verified against the model

Parsed `public/perfume_bottle.glb` directly (header → JSON chunk) rather than assuming:

- liquid POSITION bounds are `y -1.0 … 1.0`, so the top of the geometry *is* the surface the
  meniscus should sit on;
- **no material is shared between nodes** (`capDarkMaterial.001`, `pipeMaterial.001`,
  `perfumeLiquidMaterial` etc. are all distinct), so mutating one cannot bleed into another;
- cap ships as `baseColor [0,0,0]`, metallic 0.3, roughness 0.25 — left alone deliberately, since a
  clearcoat on pure black would put a hard white streak on it, which is the glare being removed.

GLSL checked structurally (8/8): `vBodyY` declared in *both* shaders and written in `begin_vertex`,
both uniforms declared and bound, all four injected blocks brace-balanced, call site passing the
measured range, and both `customProgramCacheKey`s bumped so a stale program is not reused.

### "Liquid glass" — the rim rebuilt around the reference (v12)

User supplied Apple's *Liquid Glass* as the target: a clear middle, an edge that gathers and splits
light, no hard line. Rebuilt `applyGlassEdge` into four layers: a **broad halo** (visibility), a
**thin chromatic contour** (three stepped exponents 4.6/5.6/6.6 put red widest and blue narrowest, so
the edge warms as it gathers), an **inner shade** (thickness), and an **alpha gather** (ceiling 0.66).
Dispersion is directional — warm where the key hits, cool opposite.

**The finding that matters, and it took a simulation to see it.** On a *light* page you cannot make
glass visible by adding light. The shell is a semi-transparent white layer over cream, so additive
brightness cancels against the backdrop when it composites. The only cue with real contrast is the
**darkening** — which means alpha has to be high enough in the band for that darkening to survive.
That is why every previous attempt either glared or vanished.

Simulated the composited contrast (Δ vs `#f3ece0`) across grazing angle before choosing values:

| grazing | 0.65 | 0.80 | 0.90 | 0.97 | 1.00 |
|---|---|---|---|---|---|
| original bottle | 3 | 12 | **26** | **41** | **49** |
| original cap | 15 | **47** | **91** | **130** | **138** |
| v9 (too faint) | 0 | 1 | 1 | 0 | 1 |
| **v12 bottle** | 6 | **12** | **14** | 7 | 2 |
| **v12 cap** | 8 | **16** | **17** | 7 | 6 |

The original was a *spike* — Δ138 is essentially pure white on cream, which is exactly the
"prickling". v9 was flat zero. v12 is a **broad band peaking at 14–17 that returns to neutral at the
silhouette**, which is the lens read: a soft ring of thickness, no line.

Shipped values: bottle `(rim 0.24, halo 0.16, gather 0.60, inner 0.50)` body `0.10`; cap
`(0.28, 0.20, 0.50, 0.54)` body `0.26`. The cap is deliberately denser — it is a thicker sleeve, and
the reference shows it as a distinct glass ring — so its expectations differ from the wall's.
